# YukiV6 完全重构规划：插件化中枢架构

## 一、现有架构深度诊断

### 1.1 项目定位

Project Yuki 是一个通过 QQ 平台运行的 AI 虚拟助手，核心能力：多群聊异步消息处理、RAG 长期记忆、精力值/活跃度/生物钟行为模拟、表情包动态学习与 RLHF、小女仆自主编程、多 Provider LLM 路由与故障转移。

### 1.2 当前代码的实际调用链

```
WebSocket 消息进入
    │
    ▼
main.py::napcat_listen()
    │  协议解析、群白名单、开关拦截、正反馈检测
    ▼
main.py::manage_buffer()
    │  防抖、入队、重置破冰计数
    ▼
main.py::main_process()          ← 466 行的 GOD FUNCTION
    │
    ├─ yuki.boost_activity()      ← brain.py::YukiState（万能状态桶）
    ├─ meme_processor.extract_urls()    ← vision/processor.py
    ├─ meme_processor.understand_from_url()  ← 视觉 VLM（逐张串行）
    ├─ parser.parse_all_cq_codes()      ← message/CQParser.py
    ├─ history_manager.load()           ← history_manager.py
    ├─ engine.decide_to_reply()         ← engine.py（调 LLM 判断）
    ├─ memory_rag.search_diaries()      ← memory/rag.py（RAG 双池检索）
    ├─ engine.api_reply()               ← engine.py（调 LLM 生成）
    │   ├─ build_chat_context()         ← prompts.py（拼装消息）
    │   ├─ provider.chat()              ← providers/registry.py → fallback.py
    │   ├─ 截获 [DELEGATE_TO_MAID]      ← 丢进 maid_task_queue
    │   └─ 截获 [MEME_SEARCH]           ← 调 sticker_manager
    ├─ sender.send()                    ← network/ws_sender.py
    ├─ history_manager.save()           ← 写回 JSON
    └─ engine.do_summarize()            ← 日记归档（又调一次 LLM）
```

### 1.3 八大瓶颈

| # | 瓶颈 | 严重度 | 描述 |
|---|------|--------|------|
| 1 | **main.py 是隐式中枢** | 致命 | 466 行函数式脚本，所有模块通过它手拉手耦合，新增功能必须改它 |
| 2 | **YukiState 万能状态桶** | 高 | 7 类不同状态（能量、活跃度、欲望、缓冲、日记锁、Maid队列、RLHF）全挤在一个类里，单一 asyncio.Lock() 争用 |
| 3 | **引擎过载** | 高 | YukiEngine 接收 4 个依赖 + 3 个后期注入 + 1 个循环回调，依赖关系完全不透明 |
| 4 | **串行管线** | 高 | 12 步串行链，VLM 超时→整条管线卡死，多群并发时吞吐量线性下降 |
| 5 | **Maid 边界越权** | 中 | 小女仆直接读写全局历史，通过 process_callback 硬编码回调唤醒主引擎 |
| 6 | **记忆孤岛** | 中 | RAG 和 HistoryManager 管理高度相关数据却完全独立，日记写入逻辑长在 engine.py 里 |
| 7 | **无协议标准** | 中 | 模块间通信全是直接函数调用，没有标准化的消息格式 |
| 8 | **QQ 逻辑硬编码** | 中 | QQ 的 CQ 码解析、发送格式、群白名单等全部散落在 main.py 各处，无法替换为其他平台 |

### 1.4 核心矛盾

当前系统是为 QQ 这一个平台量身定制的单体脚本。但实际需求是：**Yuki 的大脑应该是一个独立服务，QQ 只是它的"眼睛和嘴巴"之一**。未来接入 Bilibili 直播、游戏等场景时，不应该改大脑的任何代码。

## 二、目标架构：LLM 中枢 + 插件协议

### 2.1 一句话定义

**Yuki 的大脑是一个独立的 LLM 判断服务。一切外部平台（QQ、Bilibili、游戏等）都是插件，通过标准协议与大脑通信。**

### 2.2 最小逻辑流

```
                    ┌─────────────────────────────────────┐
                    │           Yuki Brain                │
                    │        （LLM 判断服务）              │
                    │                                     │
  QQ Plugin ──────→ │  1. 接收消息                         │
  (输入注册)        │  2. 搭建上下文（人格 + 记忆 + 历史）   │
                    │  3. 综合判断（是否回复）              │
                    │  4. 生成回复（或沉默）                │
                    │  5. 归还给来源插件                    │
                    │                                     │
  QQ Plugin ←────── │                                     │
  (输出注册)        └─────────────────────────────────────┘

  未来扩展：
  Bilibili Plugin ──→ Brain ──→ Bilibili Plugin
  Game Plugin ────→ Brain ──→ Game Plugin
```

### 2.3 设计原则

| 原则 | 含义 |
|------|------|
| **大脑不知道插件的存在** | Brain 只认消息协议，不关心消息来自 QQ 还是 Bilibili |
| **插件不知道大脑的实现** | 插件只管发消息、收回复，不关心 Brain 内部用了什么 LLM |
| **所有功能归属清晰** | 记忆、人格、决策 = Brain 的事；消息格式、平台 API = 插件的事 |
| **最小改动原则** | 添加新插件不需要修改 Brain 的任何一行代码 |

## 三、插件协议（Plugin Protocol）

这是整个架构的核心契约。所有插件必须遵守这套协议才能与 Brain 通信。

### 3.1 输入消息协议（Plugin → Brain）

```python
@dataclass
class InboundMessage:
    """插件发送给 Brain 的标准消息"""

    # === 来源标识 ===
    plugin_id: str          # "qq", "bilibili", "game", ...
    session_id: str         # 会话唯一标识（QQ群号、直播间ID等）
    sender_id: str          # 发送者唯一标识（QQ号、B站UID等）
    sender_name: str        # 发送者显示名

    # === 消息内容 ===
    text: str               # 纯文本内容（插件已做过平台特定解析）
    modality: str            # "text", "image", "multi"
    media_refs: list         # 图片URL、文件路径等媒体引用列表

    # === 元数据 ===
    is_bot: bool             # 发送者是否为机器人
    reply_to: Optional[str]  # 引用/回复的消息ID
    timestamp: float         # 消息时间戳

    # === 插件上下文 ===
    plugin_context: dict     # 插件自定义数据（如 QQ 的 group_id、CQ码原始数据等）
```

### 3.2 输出消息协议（Brain → Plugin）

```python
@dataclass
class OutboundMessage:
    """Brain 返回给插件的标准消息"""

    # === 目标标识 ===
    plugin_id: str           # 目标插件
    session_id: str          # 目标会话

    # === 回复内容 ===
    text: str                # 回复文本
    media_refs: list         # 附带的媒体资源
    should_send: bool        # True = 发送，False = 静默（Brain 决定不回复）

    # === 元数据 ===
    reply_to: Optional[str]  # 引用哪条消息
    metadata: dict           # Brain 附加的元数据（如情感标签、表情包ID等）
```

### 3.3 插件注册接口

```python
class PluginBase(ABC):
    """所有插件必须实现的基类"""

    @property
    @abstractmethod
    def plugin_id(self) -> str:
        """插件唯一标识"""

    @abstractmethod
    async def start(self, brain_callback: Callable[[InboundMessage], Awaitable[OutboundMessage]]):
        """
        启动插件。
        brain_callback: 插件调用此函数向 Brain 发送消息并等待回复。
        """

    @abstractmethod
    async def stop(self):
        """停止插件，释放资源"""

    @abstractmethod
    async def send_outbound(self, message: OutboundMessage) -> bool:
        """
        Brain 通过此方法将回复推送给插件。
        插件负责将 OutboundMessage 转换为平台特定格式并发送。
        """
```

## 四、Brain 内部架构

### 4.1 Brain 的职责边界

Brain **只负责**：
1. 接收标准化的 InboundMessage
2. 搭建上下文（注入人格、召回记忆、拼装历史）
3. 决策（是否回复）
4. 调用 LLM 生成回复
5. 解析回复中的指令标签（委托小女仆、搜索表情包等）
6. 将回复封装为 OutboundMessage 归还

Brain **不负责**：
- 平台特定的消息解析（CQ码、B站弹幕格式等）
- 平台特定的发送逻辑（QQ CQ码图片、B站礼物特效等）
- 平台特定的权限管理（QQ 群白名单、B站房管权限等）

### 4.3 消息处理流程（Brain 内部）

```python
# brain/server.py

class BrainServer:
    """Yuki 大脑核心服务"""

    def __init__(self):
        self.context_builder = ContextBuilder()
        self.decision_engine = DecisionEngine()
        self.response_generator = ResponseGenerator()
        self.memory = MemorySystem()
        self.state = StateSystem()

    async def handle_message(self, msg: InboundMessage) -> OutboundMessage:
        """
        处理一条入站消息，返回标准出站消息。
        这是插件调用 Brain 的唯一入口。
        """

        session_id = msg.session_id

        # 1. 状态更新（活跃度提升、精力计算）
        self.state.on_message_received(session_id)

        # 2. 决策：是否回复
        should_reply = await self.decision_engine.decide(
            session_id=session_id,
            message=msg,
            history=self.memory.get_recent_history(session_id)
        )

        if not should_reply:
            return OutboundMessage(
                plugin_id=msg.plugin_id,
                session_id=session_id,
                text="",
                media_refs=[],
                should_send=False,
                reply_to=None,
                metadata={}
            )

        # 3. 上下文搭建（人格 + 记忆 + 历史）
        context = await self.context_builder.build(
            session_id=session_id,
            message=msg,
            memory=self.memory
        )

        # 4. LLM 生成
        raw_response = await self.response_generator.generate(context)

        # 5. 解析响应（提取委托指令、表情包标签等）
        parsed = self.response_generator.parse(raw_response)

        # 6. 处理子代理委托（小女仆等）
        if parsed.has_delegation:
            self.state.submit_maid_task(session_id, parsed.delegation_task)

        # 7. 处理表情包搜索
        sticker_ref = None
        if parsed.has_meme_search:
            sticker_ref = await self.memory.sticker_manager.find_sticker(
                parsed.meme_query, session_id
            )

        # 8. 消耗精力
        self.state.consume_energy(session_id)

        # 9. 保存对话历史
        self.memory.save_turn(session_id, msg.text, parsed.clean_text)

        # 10. 归还标准消息
        media = []
        if sticker_ref:
            media.append(sticker_ref)

        return OutboundMessage(
            plugin_id=msg.plugin_id,
            session_id=session_id,
            text=parsed.clean_text,
            media_refs=media,
            should_send=True,
            reply_to=msg.reply_to,
            metadata={
                "raw_text": parsed.raw_text,
                "energy": self.state.get_energy(session_id),
            }
        )
```

### 4.4 上下文搭建器

```python
# brain/context_builder.py

class ContextBuilder:
    """负责将所有信息拼装成 LLM 可消费的 messages 列表"""

    def __init__(self):
        self.prompt_builder = PromptBuilder()

    async def build(self, session_id: str, message: InboundMessage, memory: MemorySystem) -> list:
        messages = []

        # 1. 人格设定（system prompt）
        persona = self.prompt_builder.get_persona(session_id)
        messages.append({"role": "system", "content": persona})

        # 2. 记忆召回（RAG 并行检索）
        diaries = await memory.recall(message.text, session_id)
        for diary in reversed(diaries):
            messages.append({"role": "system", "content": f"【回忆】{diary['content']}"})

        # 3. 近期对话历史
        recent = memory.get_recent_history(session_id, limit=10)
        messages.extend(recent)

        # 4. 当前消息
        messages.append({"role": "user", "content": message.text})

        return messages
```

### 4.5 决策引擎

```python
# brain/decision_engine.py

class DecisionEngine:
    """综合精力值、活跃度、欲望和 LLM 判断，决定是否回复"""

    def __init__(self):
        self.energy = EnergySystem()
        self.activity = ActivitySystem()
        self.desire = DesireSystem()
        self.biorhythm = BiorhythmEngine()
        self.provider = ProviderRegistry().get("default")

    async def decide(self, session_id: str, message: InboundMessage, history: list) -> bool:
        # 1. 强制回复：被直接称呼
        if self._is_called(message.text):
            return True

        # 2. 精力检查
        energy = self.energy.get(session_id)
        if energy < cfg.MIN_ACTIVE_ENERGY:
            return False

        # 3. 欲望计算
        desire = self.desire.compute(session_id, energy, self.activity, self.biorhythm)

        # 4. 阈值判定
        if desire >= 80:
            return True
        if desire <= 20:
            return False

        # 5. LLM 深度判断
        return await self._llm_decide(history, energy)
```

## 五、QQ 插件实现

### 5.1 职责边界

QQ 插件**只负责**：
- WebSocket 连接管理
- QQ 特定消息解析（CQ码、@、回复引用）
- 消息防抖与缓冲
- 群聊白名单/开关管理
- 视觉理解（图片 URL 提取、VLM 调用）
- 正反馈检测（RLHF）
- QQ 特定格式发送（CQ码图片、语音等）

QQ 插件**不负责**：
- 记忆管理、历史管理
- 回复决策、LLM 调用
- 人格设定、精力值计算

```python
# plugins/qq/plugin.py

class QQPlugin(PluginBase):
    """QQ 平台插件"""

    @property
    def plugin_id(self) -> str:
        return "qq"

    async def start(self, brain_callback):
        self._brain = brain_callback
        self._ws = BotConnector(cfg.NAPCAT_WS_URL, cfg.NAPCAT_WS_TOKEN)
        self._sender = QQSender(self._ws)
        self._parser = CQCodeParser(self._ws)
        self._buffer = MessageBuffer()
        self._visual = VisualProcessor()
        self._feedback = FeedbackDetector()
        self._groups = GroupManager()

        # 启动消息循环
        asyncio.create_task(self._listen_loop())

    async def _listen_loop(self):
        async for raw_data in self._ws.listen():
            if raw_data.get("post_type") != "message":
                continue

            msg = self._parse_raw(raw_data)
            if msg is None:
                continue  # 被白名单/开关拦截

            # 正反馈检测
            self._feedback.check(msg)

            # 消息防抖聚合
            aggregated = await self._buffer.enqueue(msg)
            if aggregated is None:
                continue  # 还在防抖等待中

            # 视觉理解（处理图片）
            aggregated = await self._visual.process(aggregated)

            # 构建标准入站消息
            inbound = self._to_inbound(aggregated)

            # 调用 Brain
            outbound = await self._brain(inbound)

            # 发送回复
            if outbound.should_send:
                await self._send_reply(outbound)

    def _to_inbound(self, msg: AggregatedMessage) -> InboundMessage:
        return InboundMessage(
            plugin_id="qq",
            session_id=str(msg.group_id),
            sender_id=str(msg.user_id),
            sender_name=msg.sender_name,
            text=msg.processed_text,
            modality=msg.modality,
            media_refs=msg.media_refs,
            is_bot=msg.is_bot,
            reply_to=None,
            timestamp=msg.timestamp,
            plugin_context={
                "group_id": msg.group_id,
                "raw_message": msg.raw_message,
            }
        )

    async def _send_reply(self, outbound: OutboundMessage):
        """将 Brain 的回复转换为 QQ 格式并发送"""
        group_id = outbound.session_id

        # 拆分文本和媒体（QQ 支持图文混排）
        parts = self._split_text_and_media(outbound.text, outbound.media_refs)

        for part in parts:
            await self._sender.send(group_id, part, mode="group")
            await asyncio.sleep(1.0)  # 模拟人类节奏

    async def send_outbound(self, message: OutboundMessage) -> bool:
        """实现 PluginBase 接口"""
        if not message.should_send:
            return True
        await self._send_reply(message)
        return True

    async def stop(self):
        await self._ws.close()
```

### 8.1 Bilibili 直播插件

```python
# plugins/bilibili/plugin.py

class BilibiliPlugin(PluginBase):
    @property
    def plugin_id(self) -> str:
        return "bilibili"

    async def start(self, brain_callback):
        self._brain = brain_callback
        self._room = BilibiliLiveRoom(room_id=cfg.BILI_ROOM_ID)

        @self._room.on_danmaku
        async def on_danmaku(danmaku):
            inbound = InboundMessage(
                plugin_id="bilibili",
                session_id=f"bili_{danmaku.room_id}",
                sender_id=str(danmaku.uid),
                sender_name=danmaku.uname,
                text=danmaku.text,
                modality="text",
                media_refs=[],
                is_bot=False,
                reply_to=None,
                timestamp=time.time(),
                plugin_context={"room_id": danmaku.room_id}
            )
            outbound = await self._brain(inbound)
            if outbound.should_send:
                await self._room.send_danmaku(outbound.text)

    async def send_outbound(self, message):
        if message.should_send:
            await self._room.send_danmaku(message.text)
        return True
```

**不需要修改 Brain 的任何代码。** 只需要：
1. 编写 `plugins/bilibili/plugin.py`
2. 在 main.py 加一行注册：`bilibili.start(brain_callback=brain.handle_message)`

### 9.2 各状态模块独立运行

```python
# brain/state/activity.py

class ActivitySystem:
    """群组活跃度管理（独立，不依赖任何外部服务）"""

    def __init__(self):
        self._activity: Dict[str, float] = {}

    def boost(self, session_id: str, sensitivity: float = 0.12):
        """非线性提升活跃度"""
        current = self._activity.get(session_id, 0.0)
        increment = (10.0 - current) * sensitivity
        self._activity[session_id] = current + increment

    def decay(self, session_id: str, level: float = 0.65):
        """半衰衰减"""
        if session_id in self._activity:
            self._activity[session_id] *= level
            if self._activity[session_id] < 0.1:
                del self._activity[session_id]

    def get(self, session_id: str) -> float:
        return self._activity.get(session_id, 0.0)
```

每个状态模块都是纯计算，不依赖任何外部 I/O，可独立测试。

## 十、Brain 内部：记忆系统设计

### 10.1 统一的 MemorySystem

```python
# brain/memory/__init__.py

class MemorySystem:
    """统一的记忆管理入口"""

    def __init__(self):
        self.history = HistoryStore()         # 对话历史
        self.rag = RAGEngine()               # 向量检索
        self.sticker_manager = StickerManager()  # 表情包
        self.diary_writer = DiaryWriter()     # 日记归档
        self.melting = MeltingEngine()        # 记忆熔炼

    async def recall(self, query: str, session_id: str) -> list:
        """召回与当前消息相关的记忆"""
        return self.rag.search(query, session_id)

    def get_recent_history(self, session_id: str, limit: int = 10) -> list:
        """获取近期对话历史"""
        return self.history.get_recent(session_id, limit)

    def save_turn(self, session_id: str, user_text: str, assistant_text: str):
        """保存一轮对话"""
        self.history.append(session_id, "user", user_text)
        self.history.append(session_id, "assistant", assistant_text)

    async def check_and_archive(self, session_id: str):
        """检查是否需要写日记"""
        if self.history.should_summarize(session_id):
            await self.diary_writer.write(session_id, self.history)
```

### 10.2 记忆熔炼（闲时压缩）

记忆熔炼不再通过监听空闲事件触发，而是由 Brain 的后台任务定期执行：

```python
# brain/server.py 中

async def _background_tasks(self):
    """Brain 的后台常驻任务"""
    while True:
        await asyncio.sleep(120)  # 每 2 分钟检查

        # 1. 记忆熔炼
        await self.memory.melting.melt_if_idle()

        # 2. 日记归档检查
        for session_id in self.memory.history.active_sessions():
            await self.memory.check_and_archive(session_id)

        # 3. 小女仆任务监控
        self._check_maid_tasks()
```

## 十二、与三篇技术文档的对接

### 12.1 情感建模

Brain 的 `state/` 目录可扩展 `emotion.py`，实现基于 OCC-PAD 的内部情感状态。情感状态通过 `context_builder` 注入 LLM 上下文，影响回复语气。插件端可读取 `OutboundMessage.metadata["emotion"]` 驱动视觉表达。

### 12.2 歌回系统

歌回作为独立插件实现：`plugins/singing/plugin.py`。它接收 Brain 的文字指令，本地执行 SVC/SV 推理、音高提取、口型同步，不经过 LLM 生成管线（直接由 Brain 的特殊指令触发）。

### 12.3 中枢四周架构

本方案是对"中枢四周"理念的工程简化：
- **中枢** = Brain（LLM 判断服务）
- **四周** = 各个 Plugin（QQ、Bilibili、游戏等）
- **类总线** = Brain 的 `handle_message` 方法（标准协议通信）

相比原方案的 5 Spoke + Event Bus + Redis Stream，本方案用更少的代码实现了相同的目标：**大脑与肢体分离，插件可插拔**。
