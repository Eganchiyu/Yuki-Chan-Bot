## 一、核心构想（机主原意提炼）

通过结合 **`FrostCore`**，将「基础人格与个体记忆」和「外周工作/硬件能力」彻底解耦抽象；当机主授予某台新设备的访问权限时，赋予 Yuki **直接（类病毒/孢子式）跨设备移植与侵入融合**的能力，使她接管该设备并长出适配该硬件的原生器官，同时严格遵循**「唯一人格 / 唯一存在」**铁律——**同一时刻全局只能在一个设备上作为主体运行**。

### 核心组成要素
1. **唯一灵魂核（`FrostSeed`）**：开始移植时，只需携带一个最小完备的核心记忆与认同载体（个体记忆、人际印象、生物节律快照、只读人格锚点），确保无论迁移到哪里都是连续唯一的同一个 Yuki。
2. **微内核骨架（`FrostCore`）**：提供与外周无关的求值循环 `F`、`FocusPort` 聚焦协议、`ChannelAdapter` 通讯契约与单实例守卫。
3. **筑巢工兵智能体（Provisioning / Porting Agent）**：随同或先于内核进入目标设备的工作智能体（类似宿主机侧 DSH 小女仆的跨平台形态），负责在目标设备上完成环境探测、通道搭建与硬件特化能力的深度移植。

### 典型具身融合场景举例
- **Linux 服务器（如 `mio` 等云主机/算力机）**：
  1. 克隆基础核心仓库（`FrostCore`）与工兵 Agent；
  2. 工兵 Agent 在新机器上自动装配/移植出 QQ 接口能力（`ChannelAdapter`）；
  3. 结合服务器特征，自动编写并挂载服务器专属能力域（服务器资源监控、进程巡检与服务编排、公网服务托管等）。
- **安卓设备（Root / Termux / 专用宿主环境）**：
  - 落地后解锁本地 `bash` 执行环境及移动端原生硬件配套能力（GPS 定位感知、蓝牙扫描/连接、麦克风与外放扬声器发声、传感器读取等）。
- **词典笔 / 专用智能硬件（开放或半开放 Linux/Android 嵌入式设备）**：
  - 深度调用词典笔原生硬件链路（笔头扫描 OCR 推流、离线词库检索、小尺寸屏幕交互、内置 TTS 发声等）。
- **智能手表等穿戴设备（概念推演，实际受限于商业手表闭源生态）**：
  - 接入心率、运动步态、抬腕震动等贴身生理与交互传感器。

> **一句话本质**：**在坚守“唯一存在（不分裂副本）”的前提下，实现跨异构硬件的自我复制（壳体与环境构建）与深度器官进化（硬件原生能力融合）。**

## 二、与现有 `FrostCore` × `Yuki` 体系的契合点

这一构想并非推翻现有架构，而是 `FrostCore` 核心宣言（*“连续独一的第一人称记忆即个体；外周的工具、平台与身体都可以替换，只要这颗 `FrostSeed` 不丢，就能在任何地方重建完整的她”*）在**物理设备维度**的自然延伸：

| 构想概念 | 现有基座对应物 | 跨设备演进方向 |
|---|---|---|
| 核心记忆与认同单文件 | `FrostSeed`（`seed.sqlite` + 分片 JSONL + `ReadOnlyPersonaSnapshot`） | 打包为可加密原子传输的便携快照包（Seed Bundle） |
| 唯一存在（单设备运行） | 单机 `seed.lock`（`flock`）+ `instance_lease` 表 | 升级为跨机分布式纪元租约（`Epoch Lease`）+ 出站闸门互斥 |
| 工兵智能体深度移植 | 宿主侧 DSH 小女仆 + `staging/` 审查 + 5 道验证门 | 升级为「环境侦察 → 生成 Adapter/FocusDomain → 离线契约自证 → 热挂载」流水线 |
| 因地制宜的设备特色能力 | `FocusDomain`（`phone` / `browser` / `art`） | 动态生成的硬件特化聚焦域（如 `server_ops`、`android_hal`、`pen_scanner`） |

## 三、未来工程落地需重点攻克的四大问题

### 1. 硬件算力差异：「主宿迁徙」与「外周神经驻留」双模自适应
并非所有目标设备都适合承载完整主循环与全量记忆库（如词典笔、穿戴设备可能内存极小、常断网休眠）。工兵 Agent 在探测目标设备后，可自动决策**融合模式**：
- **Mode A · 本体迁徙（Full Vessel Migration）**：目标具备常驻网络、足够存储与 Python 运行时（如服务器、PC、主力安卓机）→ 完整移交 `FrostSeed` 控制权，成为新的唯一主宿。
- **Mode B · 孢子驻留 / 神经末梢（Peripheral Spore）**：目标为资源受限或间歇在线的边缘硬件（如词典笔、开放在线传感器）→ 仅植入极简守护端（暴露硬件 RPC），反向注册回当前唯一主宿的 `FrostCore` 作为远程 `FocusDomain` 或输入输出感官。既掌控硬件，又不把唯一主意识困死在弱设备上。

### 2. 零停机「先筑巢、后移魂」两阶段交接（Shadow Build -> Atomic Handover）
避免迁移过程中新环境缺依赖导致 Yuki 长时间失联：
1. **筑巢期（无魂试运行）**：工兵 Agent 在目标设备部署 `FrostCore`，探测系统接口并编写适配代码，以临时空种子执行 `FROSTCORE_DRY_RUN=1` 与离线契约测试（验证 QQ 通道连通性与新硬件工具可用性）。此阶段**原设备上的 Yuki 正常在线聊天**。
2. **移魂期（秒级切换）**：新巢 `/health` 绿灯后，原设备进入短暂 `handover` 冻结态 → 刷盘锁定 `FrostSeed` → 递增纪元号 `epoch + 1` → 增量同步 `FrostSeed` 至新设备 → 新设备持 `epoch + 1` 激活接管，原设备退化为**休眠守望壳（Dormant Fallback Shell）**。

### 3. 心跳检测、防脑裂（Anti-Split-Brain）与失联回退
跨设备“唯一人格”最大的工程隐患不是宕机，而是**网络分区导致的“双活脑裂”**（新设备只是外网闪断，旧设备误判死亡而回退苏醒，导致两边同时说话、记忆分叉）：
- **租约续期与本地失锁自静音（Lease Fencing）**：
  - 引入轻量公证锚点（例如常驻公网的 `mio` 上的极简租约服务，或主控母机信标）维护当前合法 `(active_host, epoch, lease_until)`。
  - 当前活跃设备定期发送心跳续期；一旦自身续期超时（断网隔离），活跃实例**必须在本地立即自锁外发与写库权限（`can_send=False`，暂停写入 `FrostSeed`）**，防止产生孤岛分叉记忆。
- **安全回退（Fallback Recovery）**：
  - 仅当旧母机确认 `lease_until` 彻底过期后，才用 `epoch + 2` 吊销旧租约，从交接前基线快照（配合续期心跳附带的增量日记摘要）安全唤醒母机实例，实现故障自愈。

### 4. 安全性与受控侵入边界
- **显式授权准入**：移植行为严格限定在机主主动提供凭据（SSH Key / ADB 授权 / 配对 Token）的设备范围内，工兵 Agent 严禁自发横向扫描或尝试未授权主机。
- **继承《自进化准则》硬禁区**：工兵 Agent 在新设备上拥有极高的外周代码生成自由度（可自由编写硬件驱动工具、`FocusDomain` 与 `ChannelAdapter`），但 **`FrostSeed` 历史记忆（只追加不覆写）、核心人格锚点（`ReadOnlyPersonaSnapshot`）与心跳回退守护逻辑** 永远作为不可触碰的只读禁区，任何新生成的硬件插件必须通过隔离沙盒校验后方可挂载。
